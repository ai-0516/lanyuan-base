### 2. seed_data.py 修复（Issue #37 / PR #38）

**Bug**：seed_data.py 用完 engine 后未 `dispose()`，`asyncio.run()` 退出关闭事件循环后，连接池中 aiomysql 连接才被 GC 析构 → `__del__` 尝试 close 已关闭的 loop → 每次运行打印 `RuntimeError: Event loop is closed`（exit 0，无功能影响，纯退出噪音）。

**修复**：`__main__` 中 `seed()` 后 `await engine.dispose()`，在事件循环关闭前显式释放连接池。

## 经验教训（dev-server 运维）

1. **ssh 非交互 shell 有 banner 输出**（腾讯云 WebShell 二维码 + 代理/Chromium 启动信息）→ **scp/rsync 报 `Received message too long`**。sftp 不受影响（走 sftp 子系统，不加载 login shell），传文件用 sftp 或先修 `~/.profile` 的非交互 guard
2. **ssh 有连接频率/时长限制**：频繁或超长连接被掐（`Connection closed` / `Connection reset`），对策：操作间隔 15s+、单次命令尽量短；耗时任务（如 pip 安装）用**远程 nohup 后台 + 本地轮询日志**，而不是长连接等待
3. **systemd 日志分层**：uvicorn 进程日志 → `journalctl -u lanyuan-backend`；应用业务日志（error.log）→ `backend/logs/`（LOG_DIR）
4. 部署机 git 工作区保持干净：`manage.sh` 这类机器本地运维脚本**保持未跟踪**，不进 git，避免 pull 冲突
