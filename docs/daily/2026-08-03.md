### 决策记录

1. **缓存命中方案**：relevant 拼 user 消息而非 system——因为 DeepSeek 前缀缓存对 system 变化敏感，user 消息序列末尾变化不影响前缀命中
2. **模块级函数签名**：`select_relevant(db, user_id, message)` 不再传 provider——provider 是内部细节，调用方无感知
3. **FK 与 index**：FK 自带索引（MySQL），显式 index 冗余删除；SQLite 下 FK 不自动建索引但表小（每用户 ≤30 条）无性能问题

### 三轮 review 补充（16:30 用户追加 9 条意见，commit `cbb5463`）

**缓存设计 bug（用户 #4 指出，属实）**：原实现把 relevant 拼进「最后一条 user 消息」，但历史消息从 DB 读出时不带 relevant → 同一 user 消息两轮请求字节不一致 → 前缀缓存从第一条历史就断，只剩 system 命中。按 **Hermes 硬不变量**（system prompt byte-stable + 新内容只追加末尾）修复：**索引 + 相关记忆都拼 SYSTEM**（记忆不变则字节不变），历史消息绝不改写。查证 Hermes 源码：`memory_manager.build_system_prompt()` 注入 SYSTEM；system_prompt.py 用 date-only 时间戳保证整天字节稳定（注释明言分钟级变化会 invalidate prefix-cache）。learn-claude-code s09 同思路（索引进 SYSTEM，相关记忆注入 user 消息副本不污染原始 messages）。

### 8/3 晚 — 结构讨论与粒度设计（与用户逐点讨论，commit a6a2a93~108d65b）

**1. 目录化 harness/memory/ 包**（用户要求：外部 service 只看到一个 memory harness）：
```
harness/memory/
├── __init__.py          ← 对外唯一入口（re-export 12 个接口 + VALID_TYPES/MemoryLimitError）
├── memory.py            ← 模块级接口 + extract/consolidate（LLM 动作）+ 格式化
├── memory_provider.py   ← MemoryProvider 抽象（纯存储 ABC + 常量）
└── memory_provider_db.py← DBMemoryProvider
```
业务代码 0 残留内部路径（api 从包入口 import 常量/异常）；测试保留白盒路径（monkeypatch 需真实模块路径）。

**2. 记忆粒度 = session（用户洞察，关键）**：每轮注入+抽取是错的——session 内多轮对话连续性由消息历史天然保证，记忆只解决「跨 session」的部分。落地：
- 新增 `session:end` 事件；`/new` 时 emit，hook 从 DB 读该 session 全部消息抽取（删每轮 LLM_START 快照机制）
- 注入只做索引（`build_memory_index`，静态字节可缓存）；**不注入相关记忆**（select_relevant 动态选择是缓存杀手）
- 缓存问题的根治：记忆只在 session 边界变化 → system 字节 session 内稳定

**3. LLM 工具闭环**（system 给索引目录，LLM 按需行动）：
- `memory_get(id)`：索引格式加 `#id`（`- [user] #12 描述`），LLM 调它取单条完整 body
- `memory_add` + SYSTEM_PROMPT 引导（参考 learn-claude-code + hermes MEMORY_GUIDANCE）：明确表达偏好才写、最有价值=少问一次/少纠正一次、一周失效的不属于记忆
- 保留约束：不主动向用户提及记忆机制

**4. 分层终态（用户拍板：抽取是 LLM 动作，provider 只保存）**：
- provider = 纯存储（add/delete/get/list_all/search/count/replace_all），零 LLM
- harness 编排层：extract/consolidate 上移（共用 `_call_llm`）；`add` 超限编排（count→consolidate→仍满抛 MemoryLimitError）；**extract 直接调模块级 add**（超限判断单一真源，合并腾空间后抽取信息仍能写入）
