## 关键设计

- **v2 = v1-copy + support-mcp**：@mcp_tool 与 v1 @tool 签名对齐（name +
  result_formatter）；业务代码逐字复制 v1（同一份查库逻辑、Depends 注入、
  api_success(model)、formatter 删隐私）——隐私保护承担者与 v1 一致（formatter 参数）。
- **MCP 模式执行链**（同 v1 ToolDef.execute）：解包 api_success → _to_dict（model→dict，
  跳过 created_at/updated_at 防 MissingGreenlet）→ result_formatter 输出 JSON 字符串
  （LLM 读 formatter 投影）；无 formatter 时返回解包后的 data（结构化 dict）。
- **双形态**：HTTP = v1 语义（本人资料全量含头像，前端展示需要）；MCP = formatter
  投影（删隐私）。_to_dict 内联在 decorator（不 import v1，§6.4b 零 v1 依赖）；
  v2 模块复用 v1 tool_registry 的 strip_keys/dumps（通用工具函数，非 MCP 依赖）。
- **注入识别**：Depends(get_db)/Depends(get_current_user) 按 dep 名识别（同 v1）。

## 验证

- 单测：test_mcp_server.py 16 个，全量 **400 passed, 4 skipped**。

  无 Token → 401；用户不存在 → `data=null`。
- MCP 模式：带 _meta → formatter 输出 `{"id":42,"nickname":"桥接用户",...}`（无
  avatar/openid/unit/room）；无 _meta → PermissionError；用户不存在 → `"null"`。
