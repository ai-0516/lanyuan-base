# 2026-08-30 — v2 M2 工具桥 review：@mcp_tool 工具=endpoint 定案（PR #94）

# Dev — 实现总结

## 背景

用户 review PR #94（v2 M2 工具桥）时给出指令：**「@mcp_tool 这个标签，使用方式和
@tool 一样，直接写在 endpoint 上」**——即 @mcp_tool 的用法要对齐 v1 @tool：
工具函数就是 FastAPI endpoint（@router 与 @mcp_tool 叠加），注入参数用
`Depends(get_db)` / `Depends(get_current_user)` 声明，而不是之前按参数名
（`user_id`/`db`）识别的独立 tools/ 模块。

## 关键设计

- **单份实现双形态**：一个函数同时服务 HTTP（FastAPI Depends 解析）和 MCP
  （`_meta` 注入 user_id + 装饰器注入会话）；装饰器返回原函数，endpoint 无感。
- **注入识别与 v1 完全一致**：`Depends(get_db)` → db 会话注入；`Depends(get_current_user)`
  → user_id 注入（MCP 模式来自 `_meta`，§6.3 身份强制绑定，LLM 不可见、不可伪造）。
- **返回格式**：endpoint 返回 `api_success(...)`（项目统一响应格式，HTTP 消费）；
  MCP 模式解包 data（`{"code","data"}` → data），LLM 看到结构化 dict。
- **用户不存在**：`api_success(None)`（查询无果=正常结果，非业务失败——既有约定）。

## 验证

- 单测：`tests/test_mcp_server.py` 16 个（_meta 提取 4 + MCP 行为 4 + HTTP 双形态 4
  + schema 3 + Mount 1），全量 **400 passed, 4 skipped**（原 396 + 新增 4）。
- HTTP 双形态实测：`GET /api/v2/user/me` → `{code:0, data:{昵称/社区/楼栋/简介…}}`
  隐私字段（avatar/openid/unionid/unit/room）不返回；无 Token → 401；
  用户不存在 → `data=null`。
- MCP 模式实测（单测）：带 `_meta` → 返回对应用户 data（无 code 包装）；
  无 `_meta` → PermissionError 拒绝。
