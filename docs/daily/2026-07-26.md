## 今日成果

### 🎯 Agent 幻觉问题彻底解决 ✅

**问题 1：** LLM 不调 `create_post` 工具，编造"已发布"回复  
**根因：** 历史消息中保存的是 AI 编造的纯文字"已发布"，而非真实的 `tool_call` 结构  
**修复方案：** 消息表新增 `tool_calls`（JSON 字段）和 `tool_call_id` 字段 → 回填真实的 `tool_call/tool` 消息结构  

修改链路：
```
Message 模型（新增 tool_calls/tool_call_id） 
  → Alembic migration（异步迁移）
    → session.py（新增 save_tool_call_message / save_tool_result_message）
      → ai_service.py（agent 结束后从 get_log() 回填真实结构）
        → context.py（重建 tool_call/tool 消息给 LLM 上下文）
```

**验证：** 三次发帖均正常调用 `create_post`，创建了 post_id=19/20/21 ✅

**问题 2：** 上下文截断行为不一致（与问题 1 同根因）→ 回填后自然消失 ✅

1. **Replay 消息重建失败：** 原来只重建了 `role` 和 `content`，漏了 `tool_call_id` 和 `tool_calls` → DeepSeek API 返回 `400 missing field tool_call_id`

## 经验教训

- **脏历史污染上下文是 LLM 幻觉的常见根因** — 保存真实 tool_call 结构后，模型看到正确模式自然学会了调工具  
- **回复真实的 tool_call/tool 结构而非编造文字** — 对 LLM 行为的影响远比强化 system prompt 有效  
- **CLI 调试工具的价值** — `replay-llm` 可以在不打开前端的情况下快速验证 Agent Loop 表现  
- **不要把 TODO 写在对话里** — 建立待办列表后工作有条理很多
