## Issue #11: harness System Prompt 运行时组装（s10）✅ 实现完成

### 背景

`context.py` 里的 `SYSTEM_PROMPT` 是单一大字符串（角色定义、功能列表、行为约束、记忆说明揉在一起）。随着 #8 压缩、#9 记忆等模块加入，需要拆分为独立 section，按真实状态运行时组装并缓存。

### 方案（对齐 learn-claude-code s10 参考实现）

`PROMPT_SECTIONS` dict + `_SECTION_ORDER` 稳定序 + `assemble_system_prompt(context)` + `get_system_prompt(context)` 确定性缓存。

| Section | 加载条件 | 内容 |
|---|---|---|
| identity | 始终 | 角色定义 + 领域边界 + 行为准则（原 SYSTEM_PROMPT 拆出） |
| tools | 始终 | 可用功能列表（原拆出） |
| memory | 始终加载说明；`memory_index` 非空追加索引段 | 跨会话记忆引导 + #9 动态索引 |
| compression | 始终（#8 已合入） | 新增：压缩策略说明 + 占位符解读（LLM 遇摘要缺失时重新执行工具） |
| workspace | 按需（调用方传非空才注入） | 新增：换场景启用（管理后台等），社区对话默认空 |

**缓存设计**：`json.dumps(sort_keys)` 确定性 key + `lru_cache(maxsize=128)`。
- context 不变 → 字节不变 → API 前缀缓存命中（对齐 Hermes「不改变过去上下文」不变量）
- 记忆/会话/workspace 状态变化 → context 变 → 缓存失效重组装
- 多用户/多会话交替请求各自命中，互不覆盖

**兼容性**：

## 追加（14:30）：review 二轮 — snxly 定 session 粒度缓存

### 意见（snxly 06:23Z）

缓存目的 = 保持 system prompt 不变 → 利用 provider 侧前缀缓存降 token 成本。Hermes 在整个 session 对话期间保持 system prompt 不变；现实现用 memory_index 做 key，memory 条数增减（LLM 主动 memory_add）→ system 变化 → 缓存命中失败。**key 应直接用 session_id**。

### 改动（commit 待定）

1. **缓存粒度 content → session**：`get_system_prompt(context, session_id)`，key = `(session_id, sections_digest)`，memory_index/workspace 只参与首次组装、不参与 key → session 内冻结（新记忆下个 session 生效，对齐 Hermes 不变量）
2. **实现方式**：lru_cache 的参数即 key，无法表达「组装输入参与组装但不参与 key」→ 改手动 OrderedDict LRU（maxsize=128）
3. **无 session_id → 不缓存**（每次现组装，幂等）：避免无 session 调用共享 'default' 缓存造成隐蔽串扰（测试暴露的坑）
4. **sections_digest 保留**：PROMPT_SECTIONS 热更新（换项目/换场景）仍使缓存失效
5. ai_service 传 `session_id=str(session_id)`；build_deepseek_messages 加 session_id 参数

### 测试

- test_context.py 缓存测试重写为 session 语义（冻结/独立/无 session 现组装/sections 失效），新增 3 用例，共 17
- 全量：**231 passed, 4 skipped**（原 226 + d405514 的 2 + 新增 3），Ruff 干净
- 测试隔离：模块级缓存跨用例泄漏（无 session_id 共享 'default'）→ autouse fixture 每用例清空

### 行为变更（有意）

LLM 主动 memory_add 后，新记忆**不立即**反映到当前 session 的 system prompt，下个 session 生效——保持 system 字节稳定 → 前缀缓存持续命中。
