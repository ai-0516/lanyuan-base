devlead review PR #94（v2 M2 工具桥）返回 **Request Changes**，A 维度严重安全问题：

> `/mcp` 端点无认证 + `_meta.user_id` 可伪造 → 任意网络可达者可冒充任意用户调用

## 关键设计

- **信任前提收紧**：`_meta.user_id` 只在「已通过传输层内部认证的 client」上采信。
  唯一持有密钥的是本进程 DSH 子进程（桥），外部 client 直连 /mcp 在传输层即 401
  ——「能到达工具的 client 只有桥」+「桥注入值来自 session id 非模型输入」两层
  构成身份边界。
- **默认安全（fail-closed）**：token 未显式配置时进程内自动生成（`secrets.token_urlsafe(32)`），
  dsh_runtime 注入同值到 DSH 子进程 env——开发零配置，外部无法猜测；生产可显式
  固定 env `LANYUAN_MCP_TOKEN`（FastAPI 与 DSH 共享）。
- **不阻塞建议处理**：URL 常量收敛 + 注释（建议 1 低成本落地）；`_to_dict` 保持
  v1 内联等价（建议 2 注明低优先，v1 退役后再收敛公共 utils）。
