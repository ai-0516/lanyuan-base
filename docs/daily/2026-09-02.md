## 实现内容

### 1. 后端：历史列表 API（§10.4 数据源 = DSH 日志派生）

- **`backend/app/ai/history.py`（新增）**：`project_messages(events)` 纯函数投影——
  `user/message` → 用户气泡；`step/start` + `assistant/chunk(text-delta)` → assistant
  气泡（对齐前端流式语义 §10.1）；纯工具步骤/空回复/ reasoning-delta 不投影；
  无 turn/end 的异常中断流兜底收尾
- **`GET /api/v2/ai/session/{session_id}/messages?before_seq=&limit=`（v2/ai.py 新增）**：
  **turn 级分页**（同轮 user+assistant 永不分页——DSH 真实事件序 step/start 先于
  user/message，assistant 段起始 seq < 同轮 user seq，任何 seq 游标都会拆散一轮对话）；
  游标 = 本页最旧 turn/start 的 seq；归属校验与 /chat 一致（非 owner 403）
- **真实数据验证发现的两个关键事实**（从 MySQL 导出 661 条真实 events 验证）：
  1. `user/message` 的 content 是 **content block 数组** `[{"type":"text","text":...}]`
     而非字符串——投影/前端都要提取
  2. `events.data` 经 text() 原生查询是 **str**（SQLite/MySQL 驱动均不反序列化
     JSON 列）——投影层 `_as_dict` 显式 json.loads（否则真实数据直接崩）

### 2. 前端：ai-chat 页事件消费改造（§10.1）

- **v1 5 事件（token/done/error/message:start/retry_wait）全部退役**，改为 DSH 事件分发：
  - `turn/start` → 回合边界（重置回合状态，不建气泡）
  - `user/message` → 用户气泡（**事件流单一数据源**，删掉 v1 本地乐观渲染）
  - `step/start` → 开新 AI 气泡（若上一个气泡为空则先删——纯工具步骤无文字）
  - `assistant/chunk` → text-delta 追加当前气泡
  - `turn/end` → 收尾（reason.kind=error → 错误态「请重试」；最终气泡仍空则丢弃）
  - `error` 帧 → 后端错误（文案用后端 message，不硬编码）
- **BASE_URL 切 v2**：`constants.js` 新增 `V2_BASE_URL`（/api/v2），**仅 ai-chat 页使用**
  （业务 API 维持 /api/v1——§9.2「v1/v2 仅限 /ai/chat」）
- **历史列表**：initSession 改为 `POST /api/v2/ai/session`（拿 session_id）→ 历史从
  `GET /session/{id}/messages` 派生加载（seq 游标 + 触顶分页）；无历史（全新用户）
  → silentGreeting 自动打招呼（v2 中 Hi 会作为 user/message 渲染——事件流单一数据源
  的必然，v1「不显示 Hi」行为退役）

## 关键决策

- **历史列表投影与前端流式消费同一套语义**（step/start 建气泡、空气泡丢弃）——投影
  是「事件日志 → 用户视图」的离线版，流式消费是在线版，两者必须一致（session-surface
  心智模型：一个日志，多个投影）
- **历史分页 = turn 级**（不是消息/事件 seq 游标）：真实数据验证发现 DSH 事件序
  step/start 先于 user/message（assistant 段起始 seq < 同轮 user seq）——按 seq 分页
  会把一轮对话拆到不同页（回复先于提问）。turn/start..turn/end 是完整边界，按 turn
  取事件窗口投影，一轮必然成对出现
- **V2_BASE_URL 独立于 BASE_URL**：issue 字面「BASE_URL 切 /api/v2」仅适用于 ai-chat
  页——业务 API（用户/帖子等）按 §9.2 维持 /api/v1，全切会破坏所有业务页
- **silentGreeting 保留**：设计稿 v3-ai-chat 首屏就是 AI 主动打招呼；v2 中 Hi 作为
  user/message 渲染是事件流单一数据源的必然结果（服务端记录了什么就展示什么）

## 经验教训

- **真实数据验证不可替代**：mock 测试全绿 ≠ 真实行为正确。lanyuan_test 库 661 条
  真实 events 暴露了 3 个 mock 发现不了的问题——content 是 block 数组（非字符串）、
  data 是 str（驱动不反序列化 JSON 列）、事件序 step/start 先于 user/message（拆散
  一轮对话）
- FastAPI 测试覆盖 get_db 依赖：**必须用 `app.dependency_overrides[get_db]`**，
  patch 模块属性对已 import 绑定的 Depends 无效（09-01 的 get_current_user 同款坑）
- fake DB 要模拟真实 SQL 语义（WHERE 过滤 + DESC + LIMIT），否则 API 分页测试
  与真实行为脱节
- pnpm file: 本地插件 install 时自动跑 prepare（tsc）——Docker 阶段 1 不需要单独
  build，但显式 build 兜底幂等无害
- ⚠️ execute_code 子进程继承 hermes kernel 的 PYTHONPATH（/tmp/hermes_kernel_*）
  会污染 `python -c` 的 import（tools 包被错误解析）——跑项目脚本需清 PYTHONPATH
