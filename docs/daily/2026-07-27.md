## 今日成果

### 🎯 `@tool` 装饰器系统（上午完成）

在 FastAPI route 函数上加 `@tool` 即可自动注册为 AI 工具，零样板代码：

```python
@router.post("/posts")
@tool(name="create_post", description="...")
async def create_post(post: PostCreate, db=Depends(get_db), user_id=Depends(get_current_user_id)):
    ...
    return api_success(post)
```

**自动处理：**
- Pydantic model 参数（如 `PostCreate`）自动展平为独立字段  
- `Depends()` 参数（`db`、`user_id`）自动排除，运行时注入  
- `api_success()` 返回值自动解包取 `data`  
- SQLAlchemy model 自动转 dict（跳过 `created_at`/`updated_at`）  
- `result_formatter` 注入点，自定义 LLM 看到的摘要文本  

**当前 14 个工具已注册：** 发帖、删帖、点赞/取消点赞、评论、查看帖子、查看用户信息等  

### 🎯 towxml Markdown 渲染（方案迭代 4 轮）

| 方案 | 结果 |
|------|------|
| 1️⃣ 自写 md-parser（200 行） | 临时方案，能力有限 |
| 2️⃣ npm require('towxml') | 运行时 `module not defined` |
| 3️⃣ 拷贝到 `lib/towxml/` | 路径固定 /towxml/ 与实际不符 |
| 4️⃣ **最终：拷贝到 `components/towxml/` + 路径修复** | ✅ **官方正确用法** |

**关键发现：** towxml 的正确使用方式不是 npm 安装后在代码里 require，而是 `npm run build` 后把产物**拷贝到小程序根目录**。之前走 npm 路线是错的。

## 经验教训

- **third-party 库优先看官方文档再动手** — towxml 走了 4 轮才找到正确用法（拷贝构建产物），如果先看 GitHub wiki 能省 1 小时  
- **`server_default` / `onupdate` 的列不应出现在 Python model 中** — 既可能引发 async 懒加载问题，又是死代码（应用层不读写）  
- **base64 清洗应该序列化前递归删除，而非在 JSON 字符串中正则替换** — 正则无法删字段，只能清值  
- **测试 115 项全部通过** — 说明重构没有破坏已有功能  
- **`alembic/env.py` 加 `include_object` 过滤** — 以后 `--autogenerate` 不会误删 MySQL 中由数据库自动管理的列
