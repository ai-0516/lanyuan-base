### 登录 500 根因定位（POST /api/v1/auth/login → 500）

- 链路：`auth_service.login → wechat_client.code2session → api.weixin.qq.com`
- **根因**：微信云托管把 api.weixin.qq.com 流量本地代理（169.254.10.1）+ 平台自签 CA
  （`/app/cert/certificate.crt`，initenv.sh 注入）；httpx 用 certifi 证书库不认平台 CA →
  `CERTIFICATE_VERIFY_FAILED: self-signed certificate`
- 决策：不做临时 CA 信任，走**路线 2**（用户拍板）：前端 wx.cloud.callContainer + 后端
  信任平台注入的 `x-wx-openid` header → 彻底不调 api.weixin.qq.com

### Review 修复（PR #101 dev-lead changes_requested，2026-09-04）

dev-lead 实测抓出严重安全敞口：`x-wx-openid` 无条件信任 + 公网访问未关闭 →
HTTP 层可伪造 header 冒充任意用户建号登录（200 + JWT + 幂等复用）。修复：

- **信任门控**：新增 `WX_TRUST_OPENID_HEADER`（默认 false）——后端只在开关开启时
  才读取 `x-wx-openid`；开启前提=云托管公网访问已关闭（部署文档 .env.example 注明）。
  关闭时 header 完全忽略 → 走 code 路径（与公网访问开着时行为一致，向后兼容）
- **格式校验**：信任开启时 header openid 须匹配 `^[A-Za-z0-9_-]{1,64}$`（对齐 DB
  varchar(64)，真实微信 openid ~28 位）；非法值（超长/特殊字符）→ 40013 拒绝，不落库
  （防生产 MySQL DataError 500）
- **service 边界防御**：`auth_service.login` `if openid is None` → `if not openid`
  （空 openid 不落库）
- **前端可读错误**：`request.js` cloud 分支在 `wx.cloud`/`callContainer` 缺失时
  显式 reject（'云能力不可用：请升级微信基础库 ≥2.19.1'），替代 TypeError 空指针

测试：新增 2 用例（开关默认关闭→header 忽略走 code；开关开启→非法格式 400/合法放行）
→ 全量 **443 passed / 4 skipped**；前端 node mock 4/4（含 wx.cloud 缺失分支）；ruff 干净。
