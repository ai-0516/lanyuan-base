## 追加：Issue #22 多轮 message 显示（Dev-Lead Review 记录，20:00-21:00）

### 场景

后端 agent loop 多轮调用时每条 LLM 回复独立持久化，但前端流式接收把多轮 token 全追加到最后一个气泡（拼成一条）——重载后显示多条。根因：流中缺少「新 message 起始」边界信号。

### 修复（PR #23，dev）

新增 `message:start` SSE 边界事件。**最终协议（第三轮，用户方案）**：每条 AI 回复（有 token 的轮次，含 turn=0）的首个 token 前发 `message:start`，前端据此创建气泡——前端不预创建气泡、后端无 turn 特判，气泡生命周期完全由事件驱动。纯 tool_call 轮无 token 不发（前端不建气泡，恰好正确）；fallback 降级同样发。用户实测验收：实时显示与重载后显示一致。

### Dev-Lead Review 发现（B 维度实测）

- **场景 1-3**（正常两轮 / 首轮纯 tool_call / 单轮回归）✅ 通过
- **场景 4 fallback 降级 ❌**：`message:start` 只在 `event == "token"` 分支发出（agent.py），fallback 分支直接 `yield ("token", full_reply)` **绕过 token 分支** → 降级文案拼进上一轮气泡，前端显示 1 条、持久化 2 条（重载后不一致）——**issue #22 原问题在 fallback 路径复现**
- 修复（1c577d4）：提取 `_needs_message_start(turn)` 公共函数，token / fallback 两分支共用；补测试 `test_fallback_on_second_turn_emits_message_start`（断言 message:start 位于降级文案前）
- 最终：4 场景实测全过 + 163 passed → **Approve** ✅

### 关键洞察

1. **事件类型消费端一致性**：新增 SSE 事件（message:start）必须同步 agent.py（产出）/ ai.py（白名单）/ 前端（消费）/ 测试——4 个消费端一处不漏
2. **分支绕过风险**：同类型事件在不同分支产出时，边界逻辑要覆盖所有分支（token 分支修了、fallback 分支漏了——公共函数提取正是为此）
3. **mock 触发验证 > 静态读码**：fallback 场景仅靠读代码很难发现，实际注入 fake LLM source 触发才暴露
